CONTEXT: Building a new curl(phi)=B reconstruction module (equilibrium/substrate/curl.py) deliberately independent of the existing equilibrium.substrate.mhd module, in order to reproduce the classical straight-wire magnetostatic profile.

WHAT FAILED: mhd.py's SQ_PLAQUETTES["y"] loop uses the same (first,second,-first,-second) face order as the x and z loops. But curl_y = dA_x/dz - dA_z/dx requires the OPPOSITE cyclic pairing from curl_x/curl_z (the classic Levi-Civita curl gotcha). Under mhd.py's original convention, the tangential signal on the wire test washed out to a pure cos(2theta) artifact that looked exactly like it could be mistaken for BCC lattice dispersion anisotropy — it was not; it was this sign bug.

ROOT CAUSE: confirmed two independent ways — hand-derivation from the Levi-Civita curl formula, and the numerical straight-wire test itself. The y-axis loop was never given the mirrored pairing that curl_y's cross-term structure demands relative to x/z.

LESSON: any code path using mhd.py's _b_vec, b_vec_vectorized, step_hall, or step_frozen_in has had a flipped B_y this entire time. Per Philip, mhd.py is a peripheral MHD/instability extension, not core substrate, and was deliberately NOT patched — the new curl.py module avoids the bug by construction (face-index-to-physical-direction determined empirically from real lat.pos/lat.nb geometry, cyclic pairing built from the actual x->y->z->x rule). Before resuming any mhd.py work, or trusting any of its B-field output, fix this sign first — and be alert generally: an unexplained cos(2theta)-shaped artifact on a curl/B measurement is a signature worth checking against a sign-convention bug before attributing it to lattice anisotropy.
