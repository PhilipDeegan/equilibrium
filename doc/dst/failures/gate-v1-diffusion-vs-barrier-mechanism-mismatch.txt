CONTEXT: Every cross_scale-dependent finding in the 2026-08-17/18 curl-full spheromak investigation (circulation erosion under stepping, "no merging through step 200", the PHARE comparison) was produced using `step_cross`'s DEFAULT `gate="v1"`.

WHAT FAILED: `gate="v1"` implements continuous Fickian diffusion — proportional-always-fires, no threshold. But `doc/dst.md` itself states that through-cell translation is NOT diffusion: it's a discrete, all-or-nothing GATE condition (a collective threshold per winding). Every finding built on `gate="v1"` was therefore built on a mechanism the theory itself says is not the real one.

ROOT CAUSE: the code already implements the theoretically-correct mechanism as `gate="barrier"` (stateless, pooled per-cell drive compared against a threshold `m0`), and `doc/dst_next.md` §8 already derived a non-picked `m0` (`m0 = scaling_factor × void_limit`, `void_limit = m_p/m_Planck ≈ 7.7e-20`, giving example values `m0_neutron≈2.49`, `m0_proton≈0.16`) — but this design was never carried into any of the curl-full-dipole/circulation work. Its own open TODO ("test calibrated barrier gate against the real neutron probe") was never actually done.

LESSON: `gate="v1"` should be treated as a coarse macro approximation at best, not the mechanism the theory actually claims. Before spending more compute tuning `scale` under `gate="v1"`, re-run the circulation-erosion and curl-full-dipole-merging checks under `gate="barrier"` with a properly derived `m0` for the actual object size being tested.
